### 센서 위치

**측면(왼쪽) 기준:**
- **C (전방 카메라):** 차량 상단 전면부 중앙 (`/dev/video6`, 640x480 @ 30fps)
- **C (후방 카메라):** 차량 후면 상단 (`/dev/video4`, 640x480 @ 30fps)
- **L (LiDAR):** 차량 우측 중앙부 (RPLiDAR A2, `/dev/ttyUSB0`, 360도 2D 스캔)

## 특징

### HW (외관, 센서 위치 등)

**1. 사용하지 않은 센서는?, 그리고 그 이유는?**

모든 기본 제공 센서(카메라 2개, 라이다 1개, 초음파 6개)를 전부 사용하고 있습니다. 다만 **트랙 주행 모드에서는 초음파 센서를 비활성화**하여 운영합니다. 트랙 주행 시 초음파 센서의 오감지(노면 반사, 난간 감지 등)로 인한 불필요한 정차가 발생하여, LiDAR만으로 전방 장애물 감지를 수행하는 것이 더 안정적이기 때문입니다. 미션 모드(주차, 회피)에서는 초음파 센서를 활성화하여 근거리 정밀 감지에 활용합니다.

**2. 추가적으로 부착한 보완물은?, 그리고 이유는?**

- **서보 모터 포텐셔미터 피드백 회로:** 서보 모터(조향용 모터 드라이버)에 포텐셔미터(A0 핀)를 연결하여 실제 조향 각도를 피드백으로 읽습니다. 조향 명령 대비 실제 각도를 모니터링하여 캘리브레이션 정확도를 높이기 위함입니다. (좌회전 518 ADC = 60도, 중앙 450 ADC = 90도, 우회전 366 ADC = 120도)
- **카메라 마운트 높이 조절:** 전방 카메라를 차량 상단에 고정하여 ROI(관심 영역) 하단 45%에서 차선을 안정적으로 인식할 수 있도록 했습니다. 차량에 가까운 차선과 먼 차선을 동시에 캡처할 수 있는 최적 높이를 확보했습니다.

### SW (제어, 알고리즘, 주행 등)

**1. 주행 시, 중앙을 찾는 방법은?**

Canny 에지 검출 + 확률적 허프 변환(HoughLinesP)을 사용한 차선 인식 기반 중앙 추종 방식입니다.

1. **전처리:** 원본 이미지 → ROI 추출(하단 45%) → HSV 변환 → 흰색/노란색 마스크 분리 → CLAHE 적용 → 가우시안 블러(5x5) → Canny 에지(threshold: 25/80)
2. **차선 검출:** HoughLinesP(threshold=25, minLineLength=10, maxLineGap=150)로 좌측(음의 기울기)과 우측(양의 기울기) 차선을 분리 검출
3. **중앙 계산:**
   - 양쪽 차선 모두 검출 시: 좌우 차선 x좌표의 평균값 = 차선 중앙
   - 우측 차선만 검출 시(외곽 실선): `center = right_x - (이미지 폭 × 0.35 / 2)`
   - 좌측 차선만 검출 시(중앙 점선): `center = left_x + (이미지 폭 × 0.35 / 2)`
   - 차선 미검출 시: 이미지 중앙값 유지(직진)
4. **조향 계산:** `offset = 차선중앙 - 이미지중앙` → 정규화 → `steering = Kp × (-offset_norm)`, Kp = 0.7

> 차선 폭을 이미지 폭의 35%로 추정 (실제 트랙 도로폭 850mm 기준)

**2. 환경 변화(조도 각도)에 따른 영상 처리 방법은?**

3단계 조도 적응 전략을 사용합니다.

1. **HSV 컬러 마스킹:** RGB가 아닌 HSV 색공간에서 흰색(S: 0-40, V: 200-255)과 노란색(H: 15-35, S: 80-255, V: 80-255) 차선을 분리 추출합니다. HSV는 조명 변화에 RGB보다 강인합니다.
2. **CLAHE (대조 제한 적응 히스토그램 평활화):** clipLimit=2.0, tileGridSize=(8,8)로 적용하여 국소적 밝기 차이를 보정합니다. 그림자나 역광 환경에서도 차선 대비를 유지합니다.
3. **낮은 Canny 임계값:** low=25, high=80으로 설정하여 어두운 환경에서도 점선 차선의 미세한 에지를 검출할 수 있도록 했습니다.

추가로 흰색 마스크와 노란색 마스크를 Bitwise OR로 합성하여, 한 가지 색상이 조명에 의해 잘 안 보여도 다른 색상으로 보완합니다.

**3. 핸들 조작 각도의 한계의 극복 방법은?**

서보 모터 물리적 한계(60도~120도, 중앙 90도)로 인해 최대 ±30도 조향만 가능합니다. 이를 극복하기 위해 **소프트 스티어링(Soft Steering)** 알고리즘을 적용했습니다.

- **기울기 임계값 기반 2단계 조향:**
  - `|steering_norm| ≤ 0.35` (완만한 커브): 감소된 조향각 적용 (최대 0.3 rad ≈ 17도) → 부드러운 차선 추종
  - `|steering_norm| > 0.35` (급커브): 전체 조향각 적용 (최대 0.6 rad ≈ 34도) → 최대 회전력 사용
- **이점:** 직선/완만 구간에서 오버슈트 방지, 급커브에서는 최대 각도 활용
- **허프 변환 기울기 허용:** slope ≥ 0.12 (약 7도)까지 허용하여 완만한 커브도 감지

**4. 주행 속도를 향상시키기 위한 방안은?**

- **프레임 평균 윈도우 축소:** 3프레임 → 2프레임으로 줄여 차선 인식 지연시간을 100ms → 66ms로 감소 (30fps 기준)
- **10ms 루프 매칭:** Arduino 펌웨어 루프를 10ms 주기로 설정하고, ROS2 시리얼 타임아웃을 0.01초로 최적화하여 명령 전달 지연을 최소화
- **중복 명령 필터링:** Legacy 모드에서 동일 명령 중복 전송을 방지하여 시리얼 버퍼 과부하 없이 최대 전송 효율 확보
- **ROI 최적화:** 이미지 하단 45%만 처리하여 불필요한 연산 제거, 처리 속도 향상
- **Decision Node 20Hz 구동:** 50ms 주기로 빠른 판단-명령 사이클 유지

## 전략

### 트랙 주행 (직선, 커브, S자 코스)

**1. 사용한 센서는?, 센서를 사용한 이유?**

| 센서 | 사용 여부 | 이유 |
|------|----------|------|
| 전방 카메라 | O | 차선 인식의 핵심 센서. Canny+Hough 기반 차선 중앙 추종에 필수 |
| RPLiDAR | O | 전방 20도 범위 장애물 감지 (0.5m 이내). 트랙 위 장애물 긴급 정지용 |
| 초음파 6개 | X (비활성화) | 트랙 주행 시 노면/난간 오감지로 불필요한 정지 발생하여 비활성화 |
| 후방 카메라 | X | 트랙 주행에서는 전방 주시만 필요 |

**2. 딥러닝 사용여부?**

X (사용 안 함)

트랙 주행은 Canny 에지 검출 + HoughLinesP 기반 고전적 컴퓨터 비전만 사용합니다. 실시간 30fps 처리에 딥러닝 추론 오버헤드 없이 안정적으로 동작합니다.

**3. 어떤 알고리즘 사용?**

- **차선 인식:** Canny Edge Detection + Probabilistic Hough Line Transform
- **조도 보정:** CLAHE (Contrast Limited Adaptive Histogram Equalization)
- **색상 분리:** HSV Color Masking (흰색 + 노란색 차선)
- **조향 제어:** P-Control (비례 제어, Kp=0.7)
- **조향 보정:** 2프레임 이동 평균 필터 (노이즈 감쇠)
- **소프트 스티어링:** 2단계 조향각 매핑 (완만/급커브 구분)
- **단일 차선 보정:** 한쪽 차선만 감지 시 도로폭(35%) 기반 중앙 추정

**4. 실패했다면 이유는?**

- **급커브 구간:** 차선이 ROI 밖으로 벗어나면 일시적으로 차선을 놓쳐 직진 유지 → 코스 이탈 위험
- **점선 차선 끊김:** maxLineGap=150으로 보완했으나, 극단적 끊김 구간에서 간헐적 미검출 발생
- **S자 코스:** 빠른 좌우 전환 시 2프레임 평균 때문에 약간의 응답 지연 존재
- **조향 물리적 한계:** 최대 ±30도 제한으로 매우 급한 헤어핀 커브 대응 불가

**5. 해당 문제를 해결위한 추후 계획?**

- **PID 제어 도입:** 현재 P-Control만 사용 중이므로, D항 추가로 커브 진입/탈출 시 오버슈트를 감쇠하고 I항으로 정상상태 오차를 줄이는 PD 또는 PID 제어 도입
- **동적 속도 조절:** 조향각이 클수록 속도를 자동 감속하는 속도-조향 연동 알고리즘 추가
- **ROI 동적 조절:** 커브 진입 감지 시 ROI 영역을 위로 확장하여 더 먼 차선을 미리 인식
- **차선 예측 모델:** 이전 프레임의 차선 위치를 기반으로 다음 프레임 차선 위치를 예측하는 칼만 필터 적용 검토

### 미션 (주차)

**1. 사용한 센서는?, 센서를 사용한 이유?**

| 센서 | 사용 여부 | 이유 |
|------|----------|------|
| 후방 카메라 | O | 주차 공간의 수평 주차선 인식. 주차 완료 위치 판단의 핵심 센서 |
| 초음파 6개 | O | 주차 진입 시 주변 장애물 근접 감지 (0.2m 안전거리) |
| 전방 카메라 | O | 주차 공간 진입 전 차선 추종 유지 |
| RPLiDAR | X | 주차 시 근거리 정밀도가 필요하여 초음파로 대체 |

**2. 딥러닝 사용여부?**

X (사용 안 함)

주차선 인식은 Canny + HoughLinesP 기반 수평선 검출로 충분히 구현 가능합니다.

**3. 어떤 알고리즘 사용?**

- **주차선 검출 (parking_line_detector.py):**
  - ROI: 후방 카메라 이미지 하단 40%
  - Canny Edge Detection (low=50, high=150)
  - HoughLinesP (threshold=50, minLineLength=100)
  - 수평선 필터링: 기울기(slope) < 0.3인 선만 유효 주차선으로 인정
  - 판정 기준: 2개 이상의 수평선 검출 시 주차 공간 도달로 판단

- **주차 시퀀스:**
  1. 전방 카메라로 차선 추종하며 주차 구역 진입
  2. 후방 카메라에서 주차 종료선(수평 흰색선) 감지
  3. 정차 후 2초간 대기 (규정 충족)
  4. 후진하여 주차 구역 탈출

**4. 실패했다면 이유는?**

- **진입 각도 오차:** 주차 공간에 비스듬히 진입할 경우 수평선이 기울어져 slope > 0.3으로 필터링되어 미감지
- **주차선 색상 열화:** 주차선이 마모되거나 조명이 어두울 경우 Canny 에지 미검출
- **측면 거리 미제어:** 좌우 벽면/장애물과의 거리를 능동적으로 조절하지 않아 충돌 위험

**5. 해당 문제를 해결위한 추후 계획?**

- **주차 경로 플래닝:** 현재는 직선 진입만 지원하므로, 조향 시퀀스를 포함한 주차 경로 계획 알고리즘 추가
- **초음파 측면 피드백:** 좌우 초음파로 벽면 거리를 실시간 측정하여 중앙 정렬 유지
- **주차선 감지 강화:** HSV 색상 마스킹을 추가하여 흰색 주차선 검출 안정성 향상

### 미션 (신호등)

**1. 사용한 센서는?, 센서를 사용한 이유?**

| 센서 | 사용 여부 | 이유 |
|------|----------|------|
| 전방 카메라 | O | 신호등 영상 촬영 및 색상 분석의 유일한 센서 |
| RPLiDAR | X | 신호등 인식과 무관 |
| 초음파 | X | 신호등 인식과 무관 |

**2. 딥러닝 사용여부?**

O (사용함)

YOLO v8 (Ultralytics)을 보조 감지 수단으로 사용합니다. 주 감지는 HSV 색상 분석이며, YOLO는 HSV 실패 시 폴백(fallback)으로 동작합니다.

**3. 어떤 알고리즘 사용?**

**이중 경로(Dual-Path) 신호등 인식:**

- **경로 1 - HSV 색상 분석 (주요):**
  1. ROI 추출: 이미지 상단 영역 (x=45%, y=5%, 폭=10%, 높이=25%)
  2. HSV 변환 후 각 색상별 마스킹:
     - 빨간색: H(0-10, 170-180), S(80-255), V(80-255)
     - 노란색: H(18-38), S(120-255), V(120-255)
     - 초록색: H(45-90), S(80-255), V(80-255)
  3. 각 마스크의 픽셀 비율 계산
  4. 최고 비율이 8% 이상이고 2위와의 차이가 5% 이상이면 해당 색상으로 판정
  5. V(밝기) ≤ 60이면 신호등 꺼짐(OFF) 판정

- **경로 2 - YOLO 객체 감지 (폴백):**
  - YOLO v8 모델로 `traffic_light_red/yellow/green/off` 클래스 검출
  - 신뢰도 임계값: 0.5
  - 쿨다운: 200ms (CPU 부하 방지)
  - HSV 결과가 불확실(UNKNOWN)할 때 보조 판단

- **Decision Node 연동:**
  - RED → 정차 (speed = 0.0)
  - YELLOW → `stop_on_yellow=true`일 때 정차
  - GREEN → 정상 주행 (cruise speed)
  - 상태 유지: 2초간 미감지 시 UNKNOWN 전환

**4. 실패했다면 이유는?**

- **ROI 위치 고정:** 신호등 위치가 예상과 다르면(높이/좌우 편차) ROI에 포함되지 않아 미감지
- **역광/반사:** 강한 역광 시 HSV 밝기값이 왜곡되어 색상 오판 가능
- **YOLO 추론 시간:** GPU 미사용 환경에서 YOLO 추론이 느려 실시간 대응 어려움

**5. 해당 문제를 해결위한 추후 계획?**

- **동적 ROI:** YOLO로 신호등 바운딩 박스를 먼저 검출한 후, 해당 영역만 HSV 분석하는 2단계 파이프라인
- **신호등 추적:** 한번 감지된 신호등 위치를 트래킹하여 ROI를 동적으로 이동

**1. 사용한 센서는?, 센서를 사용한 이유?**

|------|----------|------|
| RPLiDAR | O | 전방 20도 범위 장애물 감지 (0.15~0.5m). 넓은 범위 스캔에 유리 |
| 초음파 6개 | O | 근거리(0.2m 이하) 정밀 감지. LiDAR 사각지대 보완 |
| 전방 카메라 | O | 비전 기반 장애물 감지 (HSV+Canny). 카메라 ROI 내 장애물 바운딩 박스 검출 |
| 후방 카메라 | X | 회피 주행 중 후방 감지 불필요 |

**2. 딥러닝 사용여부?**

X (사용 안 함)

장애물 감지는 LiDAR 포인트 클라우드 거리 필터링 + 초음파 거리 + HSV/Canny 비전 검출로 구현합니다.

**3. 어떤 알고리즘 사용?**

**3중 센서 융합(Multi-Sensor Fusion) 장애물 감지:**

- **LiDAR 기반 장애물 감지:**
  - 전방 각도 범위: 350도~10도 (전방 20도 원추형)
  - 유효 거리: 0.15m ~ 0.5m
  - 출력: 장애물 유무 Boolean 플래그 + 최소 거리값
  - 토픽: `/perception/obstacle_flag`, `/perception/obstacle_distance`

- **초음파 근접 감지:**
  - 전방 3개 센서 (Front, Front-Left, Front-Right) 활용
  - 안전 거리: 0.2m 미만 시 긴급 정지
  - 토픽: `/ultrasonic/ranges`

- **비전 기반 장애물 감지:**
  - HSV 채도(saturation < 60) + 밝기(value < 40) 필터로 어두운 장애물 검출
  - Canny Edge (low=80, high=160) + 최소 면적 600px² + 최소 높이 20px
  - 장애물 위치에 따른 가중치 바이어스 → 장애물 반대 방향으로 조향 유도

- **Decision Node 장애물 처리:**
  ```
  LiDAR 장애물 감지 → 정지
  초음파 전방 < 0.2m → 정지
  비전 장애물 감지 → 바이어스 조향
  ```

**4. 실패했다면 이유는?**

- **수동 회피만 가능:** 현재는 장애물 감지 시 정지만 수행하고, 능동적인 회피 경로 생성이 없음
- **LiDAR 사각지대:** 2D LiDAR이므로 높이가 낮은 장애물은 스캔 평면 아래로 빠져 미감지
- **비전 감지 한계:** HSV 기반이므로 밝은 색상의 장애물은 채도/밝기 조건에 걸리지 않아 미감지

**5. 해당 문제를 해결위한 추후 계획?**

- **능동 회피 알고리즘:** Bug Algorithm 또는 VFH(Vector Field Histogram) 기반 장애물 회피 경로 생성
- **장애물 추적:** 감지된 장애물의 위치를 프레임 간 추적하여 이동 장애물 대응
- **YOLO 장애물 감지:** 딥러닝 기반 객체 인식으로 다양한 형태/색상의 장애물 범용 감지
